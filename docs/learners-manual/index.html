What you are learning

Crew Platform is a personal software-building workspace based on the upstream Super Simple Software Factory. Vue provides the controls, Bun serves the local API, Python coordinates workflows, and Pi handles coding-agent turns. SQLite records the trace. Your router selects models when Crew requests auto.

The User's Manual teaches operation. This manual teaches preparation, diagnosis, and modification. Reading one lesson at a time is enough; you do not need to memorize the architecture before trying the app.

Current status

The UI build and isolated controls have passed checks. A live router run reached planning and the token guard stopped it. A full real generated app remains unverified. Future grants, permits, and other verticals are not implemented.

The preferred codebase-to-course and walkthrough skills were not available in this session. These lessons, checkpoints, and interactive maps implement equivalent teaching approaches; those skills were not invoked.

Get it running from source

Already have a prepared folder? Double-click Start-Crew.cmd and use the User's Manual. The following steps are for someone preparing or modifying the source.

1. Prepare the tools

Use Windows PowerShell for these examples. Open Start, search for PowerShell, and open it normally. Administrator access is not ordinarily required. Install Git, Bun, uv, Node.js, and Pi from their official instructions. Pi is the coding-agent CLI, not the conversational Pi companion service.

Official references: Git, Bun, uv, Node.js, and Pi. Crew's Python workflows require a Python runtime; uv can manage one. The repository does not pin a minimum compatible Pi release, so verify the installed CLI rather than assuming any unrelated tool named pi will work.

git --version
bun --version
node --version
uv --version
pi --version

What you should see: a version for each tool. “Command not found” means installation or PATH needs attention. PATH is the list of folders Windows searches for a program. Open a new terminal after installing a tool.

2. Obtain the source

Choose a distinct folder name so another checkout cannot be confused with this one. Do not clone over existing work.

Set-Location D:\dev
git clone https://github.com/DSahms/Antigravity-SSSF.git crew-platform
Set-Location .\crew-platform
git switch flow-and-onboarding

The changes described here may be local and uncommitted until the maintainer publishes them. A fresh clone is not guaranteed to contain this build. If the branch is unavailable, inspect the repository's actual branches rather than inventing one.

3. Install the interface dependencies and build

Set-Location .\studio
bun install
bun run build
Set-Location ..

Why: dependencies provide Vue, the compiler, and the local web tooling. The build produces the interface that the launcher serves. Lockfiles should be reviewed together before changing package managers.

4. Launch

In File Explorer, open the project folder and double-click Start-Crew.cmd. Or, for visible development logs:

Set-Location .\studio
bun run server/index.ts

Open Crew on this computer. The service binds to loopback, so it is not a public hosting setup. Vite development mode uses port 5173 and proxies API requests to port 4620.

5. Configure the router and try a small job

Start your router independently. In Settings, save the endpoint, paste the accepted key or dummy key, select auto if supported, and test the connection. The installed Pi must support the router's streaming chat/tool format. A four-token connection reply verifies basic connectivity, not full tool compatibility.

Create a separate project in Crew. Describe a tiny app with one testable behavior. Complete the interview, approve twice, and inspect the trace. Do not raise token limits just to make a failing loop disappear.

1 · Follow a job

Goal: separate a roster from a workflow. A roster describes agent roles and configuration. A workflow defines the ordered steps that use those roles. Selecting a full roster does not mean every role participates in every job.

REQUIRED_AGENTS = ["planner", "builder", "reviewer", "documenter"]

Plain English: the full SDLC script needs those four roles. It doesn't automatically use interviewer, researcher, or specialist in the build phase.

Try it: open Review & Approve and compare Scout Recon with the full workflow without starting either. Look at the named phases. Go deeper: read studio/server/launcher.ts and adws/adw_simple_sdlc.py.

2 · Follow a connection

Goal: know which settings actually reach an agent. Settings are persisted in a profile. At launch, runtime.ts creates a private Pi model registry and rewrites the selected roster's runtime model names to those registered providers. The saved source roster is preserved.

agent.model = `${provider}/${profile.model}`;
env[keyName] = profile.apiKey || "none";

Plain English: use the chosen profile's model, and supply its credential through the child environment. The generated model registry contains an environment reference, not the secret itself.

Try it: select Interviewer and inspect its endpoint. With auto, the router chooses the model. Verify a tiny connection reply before a full job. Go deeper: compare profiles.ts, runtime.ts, and agent_pi.py. The runtime registry currently assumes 128,000 context tokens and 8,192 maximum output tokens; it does not infer your router's actual per-model limits.

Check your understanding

The endpoint is localhost. Does that prove the inference is free and stays on your computer?

3 · Understand approval

Goal: explain why a job must be reviewed again after a settings change. The approval stores the reviewed text and a hash of the roster and profiles. The launcher checks that fingerprint before execution. A hash is a compact fingerprint; it is not encryption.

if (r.executionHash !== this.executionHash())
  throw new Error("Connection or roster settings changed after approval. Review and approve the job again.");

Try it: approve a test brief, change a saved connection, and observe that the old approval cannot authorize a run. Do this in an isolated test project. Go deeper: inspect approvals.ts and the corresponding core regression test.

Check your understanding

You approved local routing, then changed the reviewer connection. What happens next?

4 · Let Python own the checks

Goal: distinguish an agent's report from evidence. Python parses structured reports, runs validation, and controls bounded correction rounds. .crew-quality.json supplies real argument lists for test, lint, typecheck, and build commands. Missing commands fail rather than silently passing.

{
  "test": ["node", "--test"],
  "lint": ["node", "--check", "app.js"],
  "typecheck": ["node", "--check", "app.js"],
  "build": ["node", "--check", "app.js"]
}

Plain English: this small JavaScript example checks tests and syntax. It is not a substitute for a TypeScript compiler or a style linter in projects that need them. Configure checks for the actual project.

Try it: deliberately break one small behavior test in a disposable app and run its test command. A meaningful test should fail. Go deeper: quality.py executes argv lists; permissions.py hashes file contents and restores disallowed changes, including existing uncommitted contents. This is after-the-fact enforcement, not an operating-system sandbox.

Check your understanding

The agent says “tests passed,” but the test command is echo. Can the job be considered verified?

5 · Read the trace and recover

Goal: find the failed step without rereading an entire transcript. Sessions contains phase status and timing, tool records, reports, and gates. Usage events record model turns. The launcher polls those events and stops when the reporting threshold is reached.

SELECT COALESCE(SUM(tokens), 0) AS total_tokens
FROM events WHERE adw_id = ? AND type = 'usage';

Plain English: add reported usage for this run. A turn can report many tokens at once, so the threshold may be exceeded before Crew knows. This is why a token cap cannot promise an exact monetary ceiling.

Try it: open an unfinished run and locate its last phase, token report, and stop reason. Keep its files for inspection. Go deeper: tracer.py defines records, db.ts reads them, and launcher.ts manages process control. Windows Stop uses process-tree termination; forced termination may leave trace records without clean finalization, even when the launcher records stopped.

Updating an engine fix requires attention to the upstream stamping templates: freshly created projects copy the active engine, but the legacy stamp installer uses .claude/skills/sssf/templates. Do not overwrite an existing project's machinery or prompts with force without reviewing differences.

Validation

Set-Location .\studio
bun run typecheck
bun test test/core.bun.test.ts
bun run build
Set-Location ..
uv run adws/test_permissions.py

The core tests use temporary projects, a simulated interview endpoint, and Windows child-process termination. They make no paid provider calls. The optional studio/scripts/verify-router.ts performs a real isolated workflow with a 12,000-token reporting cap and an eight-minute timeout; it can incur provider usage. Do not run it casually.

Storage and lifecycle

Profiles, interview state, approvals, and launcher logs are private runtime files, not source. SQLite uses WAL to allow readers during writing. Browser drafts are separate from server interview state. No schema migration should discard existing approvals or silently carry them to another case. Legacy approvals without the new execution fingerprint must be reviewed again.

Release and extension boundaries

There is no installer or automated release pipeline yet. Compile the frontend, verify startup, and preserve runtime data during updates. The job-type and case foundation documents are plans; the software engine still has repository and Git assumptions. A future generalized case abstraction must not be documented as delivered until tested with a non-software job.

Maintaining these manuals

These HTML files are the authoritative manual source. Shared CSS and JavaScript live in docs/manual-assets. Edit the relevant section once, validate links/search/quizzes, then inspect desktop and mobile rendering. Preserve distinctions between planned, implemented, and verified features. Do not copy credentials into examples or screenshots.

Something broke

The build cannot launch a dependency executable

Use the explicit Node commands in package scripts. If files are missing, install dependencies in studio and rebuild. Preserve lockfiles and review their differences instead of deleting them blindly.

Python interprets thinking: off as a Boolean

YAML parsers differ: Python's loader treats unquoted off as false. The runtime writer quotes strings. In a manually edited roster, quote "off". Preserve the string type through config validation.

Pi cannot find the custom model

Inspect the private runtime registry and PI_CODING_AGENT_DIR/PI_MODELS_PATH wiring without displaying credentials. Confirm the selected model is registered under its Crew role provider. On Windows, Crew invokes Pi's Node entry point directly to avoid passing prompts through a shell wrapper.

A job says success but the app is broken

Inspect the chosen workflow's checks, the actual test command, and reviewer evidence. Some lightweight workflows intentionally lack a full build/test/review cycle. Never broaden a success claim beyond the checks performed.

A permission violation was detected

Read the named paths and restore outcome. Content-aware rollback preserves pre-agent file bytes; symlink changes require manual recovery. This mechanism does not contain access outside the repository. Use isolated projects and review agent capabilities.

Tests fail only inside a restricted execution environment

Local HTTP servers and uv's runtime cache may be inaccessible inside that environment. Verify the failure before treating it as an application defect. Use an approved isolated test run with appropriate access; do not turn off system-wide protections.

Vocabulary, without the gatekeeping

Deterministic coordinator
Program code that chooses steps and evaluates explicit conditions, rather than leaving those decisions to an agent's judgment.
Envelope
A structured report passed between phases.
Acceptance check
A test or review criterion that shows whether a requested result was achieved.
Git repository
A project folder with recorded versions of its files.
WAL
SQLite's write-ahead log: a mode that supports reading while another process writes.
Adapter
A boundary that connects a shared system to a particular kind of work.
Tacit knowledge
Experience and constraints someone knows but may not think to explain explicitly.
